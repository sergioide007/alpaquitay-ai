The trust loop

Autonomy should be earned at every step.

A request does not jump straight to a filesystem write. The harness gathers evidence, picks a bounded route, and leaves a receipt you can inspect.

01

Perceive

Fingerprint the real workspace, stack, source directories, and platform commands.

03

Generate a bounded unified diff. Protected paths and likely secrets are blocked.

real exit codes

Built for engineering systems

More control plane. Less prompt wrapper.

The assistant works inside the lifecycle your team already cares about: requirements, architecture, quality, delivery, and maintenance.

GATE / SDLC

Executable gates, not green labels.

Done requires no pending diffs, a verified platform contract, and fresh build/test evidence. A known command is not treated as a successful run.

ROUTE / DEEP

Specialists with receipts.

Security, QA, architecture, DevOps, FinOps, AI, cloud, and more—selected deterministically and limited to one registered shell.

Security · 92%QAArchitectureDevOpsFinOps
WRITE / DIFF

Diff first. Always reviewable.

Generated work remains In Progress until you approve the exact change set.

+ review(change)
+ checkpoint.save()
− writeImmediately()
SIGNAL / DORA

Delivery signals with honest labels.

Repository-derived frequency, traceability, and change-failure proxies are visible without pretending Git history is a deployment system.

LIMIT / DEBT

Debt that can stop the line.

Risky decisions add agentic debt. Verified Done, onboarding, and safe applies pay it down. The ceiling blocks new Build work.
