# Architecture diagrams

These are Alpaquitay AI's official diagrams. Click any of them to see it full screen. They are available as SVG (editable) and PNG in [`docs/diagrams/`](https://github.com/sergioide007/alpaquitay-ai/tree/main/docs/diagrams), generated by the Python scripts in `docs/diagrams/src/`.

## 1. The harness pipeline

![The harness pipeline](diagrams/01-harness-pipeline.svg "Perceive, decide, the Flash, Build and Deep lanes, and the evidence layer.")

How a request travels through the harness: the project is perceived, a lane is chosen, the change is previewed, guarded, verified and logged. Explained in [How the harness thinks](../harness/).

## 2. Inside the extension

![Extension architecture](diagrams/02-extension-architecture.svg "Composition root, Hub, harness core, capability layers and external systems.")

The components of the extension host: the composition root, the Hub, the harness core, the capability layers (providers, tools, skills, documents, local engine) and the external systems it talks to.

## 3. Sequence of an SDD task

![Task sequence](diagrams/03-sdd-task-sequence.svg "Plan, generate, diff, approve, apply, prove and outcome.")

What happens between dragging a card to *In Progress* and it reaching *Done*. Explained in [Work](../work/#2-the-board).

## 4. SDLC gates

![SDLC gates](diagrams/04-sdlc-gates.svg "Six phases with their keywords, lane and exit gate.")

The six phases and what each one requires to move on. Explained in [How the harness thinks](../harness/#the-six-sdlc-phases-and-their-gates).

## 5. Providers and the privacy boundary

![Providers and privacy](diagrams/05-provider-privacy.svg "The local path unchanged; the cloud path with data hidden and value-free records.")

How the provider is chosen and what happens to your text on each path. Explained in [Providers](../providers/#the-privacy-boundary).

## 6. Specialist orchestration

![Specialist orchestration](diagrams/06-domain-orchestration.svg "The central agent, the orchestrator and the registry of 17 specialists.")

The central agent (privacy, knowledge retrieval, orchestration and refinement), the orchestrator and the specialist registry. Explained in [Agents](../agents/).

## 7. Hexagonal specialist

![Hexagonal specialist](diagrams/07-hexagonal-domain-shell.svg "Primary ports, use cases, domain, guardrails, secondary ports and adapters.")

The ports-and-adapters architecture of each specialist: the domain never depends on the infrastructure.

## 8. Architecture inference

![Architecture inference](diagrams/08-arch-inference.svg "From manifests, compose and spec to the canvas and the IaC export.")

The evidence behind the Architecture tab's diagram. Explained in [Architecture](../architecture/#where-the-diagram-comes-from).

## 9. Generated Clean Architecture

![Clean Architecture](diagrams/09-clean-architecture.svg "Clean Architecture structures for Java Spring and React.")

The structures the project builder generates for Java Spring and React.

## 10. Document agent

![Document agent](diagrams/10-docs-agent.svg "Adapters, intent, confirmation, edit and analysis runs, review, apply and verify.")

The Docs tab flow, from reading the format to verifying the written file. Explained in [Docs](../docs/).

## 11. Local engine

![Local engine](diagrams/11-local-gemma-engine.svg "Extension host, engine panel with its cache, static CDN and local GPU.")

How the model is downloaded, verified, cached and run on your GPU. Explained in [Local engine](../local-engine/#security-why-you-can-trust-what-is-downloaded).
